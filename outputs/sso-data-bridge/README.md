# SSO Data Bridge

一个无本地服务的 Chrome / Edge Manifest V3 扩展，用于复用当前站点的 SSO 登录态，自动调用可配置的 JSON 接口、执行分页查询，并把结果保存到扩展 IndexedDB 中。

结果页 `analyzer.html` 是扩展自带页面，默认以 JSON 展示完整响应结构，也可以复制或下载完整 JSON。

## 安装

1. 打开 `chrome://extensions`。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本目录：`outputs/sso-data-bridge`。
5. 打开目标数据网站并完成 SSO 登录，然后点击浏览器工具栏中的扩展图标。

Edge 也可以在 `edge://extensions` 中通过“加载解压缩的扩展”安装。

扩展当前请求 `<all_urls>` 权限，因为它需要支持用户自行填入的不同数据接口。接口 URL、请求头、请求体和分页路径都只保存在浏览器本地。

## 最快使用流程

1. 在目标网站登录，打开包含数据的页面。
2. 打开 DevTools，选择“SSO 数据接口”面板。
3. 在页面中执行一次筛选或查询。
4. 在请求列表中选择实际返回数据的 XHR、Fetch 或 JSON 请求。
5. 点击“填入侧边栏配置”，扩展会自动填充 URL、Method、Headers、Body、分页字段和响应路径。
6. 检查推断结果，必要时手工修改。
7. 在侧边栏点击“运行抓取”。
8. 点击“JSON 工具”查看、复制或下载完整结果。
9. 点击“分析”进入数据分析工作台。

## 数据分析工作台

每个新抓取任务都会保留原始分页响应，并保存对应的接口配置。打开分析工作台后，可以选择分页响应中的任意数组路径作为原始数据表。

工作台支持：

- 自动列出响应中的数组字段，例如 `data.rows`、`result.list`
- 将数组内对象的子字段递归展开，并通过点路径表示嵌套字段
- 取所有对象字段的并集作为原始二维数据表
- 勾选需要展示的字段
- 修改字段别名
- 上下移动字段顺序
- 一键全选或反选字段
- 一键隐藏所有未选中字段，并可再次显示
- 一键把未选中字段整体移动到字段列表顶部
- 为字段值设置二次映射，例如将状态 `1/2/3` 映射成不同文本
- 支持条件字段派生，例如“商品名等于可乐时，将价格覆盖为 2”
- 字段派生规则通过 JSON 批量导入，不需要逐条添加
- 派生规则中的字段名可以使用原始路径或字段别名；目标别名会解析到对应的原始字段
- 字段映射会进入筛选、透视、图表和导出模板
- 使用递归分组组合筛选条件，例如 `a OR (b AND c) AND d`
- 常用筛选条件使用唯一名称保存，可以在子组件中通过 AND/OR 分组嵌套引用
- 常用条件可以重新载入原条件编辑并更新，不需要删除后重新保存
- 时间字段自动使用日历日期选择器
- 筛选运算符包括等于、不等于、包含、不包含、大于、小于、为空、属于列表等
- 保存多个报表模板
- 在侧边栏中直接打开已保存报表模板
- Source、Fields、Mapping、Filters 区域可以折叠隐藏
- 左侧配置面板支持整体隐藏，Dashboard 会自动占满页宽

导出的“看板本地 HTML”包含当前筛选后的静态看板内容，不依赖扩展或本地服务。

导出的“看板规则”包含请求配置和报表模板，不包含抓取到的原始数据。将规则文件通过侧边栏的“导入”按钮载入后，会同时恢复接口请求和报表子模板。重新运行请求并打开分析页即可匹配这些模板。

“导出当前看板”会只导出当前 Dashboard 模板及常用条件，不包含接口请求；可以在当前数据集中直接导入，也可以在侧边栏选择现有接口后导入。

即使当前 Dashboard 尚未点击“保存”，导出规则也会包含内存中的当前状态，包括字段别名、字段值映射、字段派生映射、子组件、组件筛选和常用条件。侧边栏导入完成后，已经打开的报表页会自动刷新并应用导入结果。

## Dashboard 组件

默认看板会自动选择适合的日期、分类和数值字段，生成记录数、二维表格、条形图、饼图、折线图和堆积条形图。

每个组件可以独立配置：

- 指标卡
- 二维表格
- 数据透视表
- 条形图
- 饼图
- 堆积条形图
- 折线图
- 行维度
- 系列维度
- 计数、求和、平均值、最小值、最大值、去重计数
- 指标字段
- 指标或维度排序
- 展示条目上限
- 每个组件支持独立递归筛选，并与全局筛选结果组合
- 条形图默认不限制条目，通过横向滚动避免横轴名称重叠
- 条形图会根据最长横轴文本动态增加宽度和底部空间，避免文字被截断
- 横轴标签支持滚动展示或自动换行
- 图表数值默认显示，可单独关闭
- 饼图默认使用“数量; 百分比”标签，可选择在前方增加图例文本；小扇区自动使用导引线
- 饼图、条形图和堆积条形图的小面积数值都支持导引线、缩小字体和鼠标悬停三种策略
- 统计字段支持展示别名
- 支持为分类、饼图扇区、折线、堆积系列配置颜色
- 饼图图例数量超过阈值时切换为纵向排列，默认阈值为 6
- 饼图默认使用整行宽度，避免半宽布局下尺寸过小
- 任意组件支持配置 `0.5` 到 `3` 倍的缩放比例，并随模板保存
- 饼图可使用半宽布局，饼图自身保持可读尺寸并允许横向查看
- 二维表格支持分页、每页数量、当前页/总页数和全量数据 Excel 导出
- 半宽或整行布局

组件可以通过上下移动或拖动缩略卡调整 Dashboard 编排顺序；拖拽占位超过目标组件 10% 面积时，其他组件会按 Grid 自动避让。

支持导出：

- 整个看板 PNG
- 单组件完整 PNG，包含横向滚动区域内的全部内容
- 完整页 PNG 与沉浸态 Dashboard PNG
- 当前 Dashboard 本地 HTML
- 请求配置与报表模板组成的完整规则 JSON
- 仅当前 Dashboard 与常用条件组成的独立规则 JSON
- 在分析页导入规则后，报表模板会持久化到扩展本地存储
- 恢复默认配色和恢复默认编排都需要二次确认

## DevTools 请求监听

扩展会在开发者工具中增加一个名为“SSO 数据接口”的面板。

面板直接使用 DevTools 当前的 Network HAR 数据，不会占用 `chrome.debugger` 调试连接，因此可以和正常的 Network 面板同时使用。

功能包括：

- 读取打开面板前已经完成的请求
- 实时监听后续 XHR、Fetch 和 JSON 请求
- 按 URL 和请求类型过滤
- 隐藏 OPTIONS 预检请求
- 查看请求头、请求体、响应 JSON
- 自动推断页码、offset、cursor 和每页条数参数
- 自动推断 `rows/list/records/items` 等数据数组路径
- 自动推断 total、pageCount、hasNext 和 nextCursor 路径
- 按响应首行推断常用去重字段
- 将选中的请求写入扩展本地存储并回填侧边栏

DevTools 标签空间不足时，“SSO 数据接口”可能显示在顶部标签栏右侧的“More tabs”菜单中。

如果侧边栏当前没有打开，选中的请求仍会保存；下一次打开侧边栏时，扩展会自动载入这条捕获配置。

## 请求配置

### 当前页面模式

扩展会把请求注入当前标签页的主世界执行，因此浏览器会自动携带该站点的 Cookie，包括 SSO 站点设置的 HttpOnly Cookie。

这是 SSO 数据站点的推荐模式。

接口 URL 可以填写完整地址，也可以填写以 `/` 开头的同源相对路径，扩展会以当前标签页地址为基准解析。

### 扩展后台模式

扩展后台直接发送请求，并显式使用 `credentials: "include"`。此模式适合公开接口或不依赖页面会话的接口。

由于现代浏览器对第三方 Cookie 和 SameSite 有限制，后台模式不一定能复用所有 SSO 会话。

### 页面变量

请求 URL、请求头和请求体字符串中可以使用：

```text
{{timestamp}}
{{uuid}}
{{date}}
{{isoDate}}
{{meta:csrf-token}}
{{input:csrf-token}}
{{cookie:XSRF-TOKEN}}
{{localStorage:some-key}}
{{sessionStorage:some-key}}
{{global:window.some.path}}
```

`{{input:csrf-token}}` 会查找 `name="csrf-token"` 的 input 或隐藏 input，并读取它的 `value`。该查找也支持普通 Shadow DOM。

不要手工填写 `Cookie` 请求头。浏览器负责携带 Cookie，扩展也会在保存和运行时拒绝手工 Cookie。

## 分页配置

支持三种策略：

- `page`：页码分页，例如 `pageNum: 1, 2, 3`
- `offset`：偏移分页，例如 `offset: 0, 50, 100`
- `cursor`：游标分页，使用响应中的 `nextCursor`

分页参数可以写入：

- JSON Body
- Query String
- Header

### 页码示例

请求体：

```json
{
  "filters": {
    "status": "active"
  }
}
```

分页配置：

```text
分页类型: page
参数位置: JSON Body
页码参数: pageNum
每页条数参数: pageSize
数据数组路径: data.rows
总数路径: data.total
```

扩展会在每次请求前写入：

```json
{
  "filters": {
    "status": "active"
  },
  "pageNum": 1,
  "pageSize": 50
}
```

### Cursor 示例

假设响应为：

```json
{
  "data": {
    "list": [],
    "hasNext": true,
    "nextCursor": "aGVsbG8="
  }
}
```

配置：

```text
分页类型: cursor
cursor 参数名: cursor
数据数组路径: data.list
hasNext 路径: data.hasNext
下一页 cursor 路径: data.nextCursor
```

## 停止条件

扩展会综合检查以下条件：

- 达到最大页数
- 当前页数组为空
- `hasNext` 为 `false`
- cursor 已为空
- 已抓取数量达到 `total`
- 当前页达到 `pageCount`
- 未提供 `total/hasNext` 时，当前页不足 `pageSize`

如果后端会把 `pageSize=100` 限制为实际的 20 条，请关闭“遇到不足一页就停止”，或者改为使用 `total`、`hasNext`、`pageCount` 中的至少一个元数据。

## 数据通信

```text
DevTools 请求捕获面板
    |
    | HAR + onRequestFinished
    v
自动推断请求和分页参数
    |
    | chrome.storage + runtime message
    v
Side Panel
    |
    | chrome.runtime message
    v
Background Service Worker
    |
    | chrome.scripting.executeScript
    v
当前标签页
    |
    | 同源 fetch + 自动 Cookie
    v
目标接口
    |
    v
扩展 IndexedDB
    |
    | runtime message + 共享存储
    v
analyzer.html
    |
    | 原始分页响应 + 数据集元数据
    v
report.html
    |
    | 字段建模、筛选、透视与图表
    v
报表模板 / PNG / HTML / 规则导出
```

整个链路不使用本地 HTTP 服务。

## 性能与版本回退

报表工作台会缓存字段展开、字段派生、字段值映射和组件筛选结果，避免同一批数据在多个图表组件中重复计算。2000 行测试数据在当前实现中首次完整渲染约几十毫秒，具体取决于设备和浏览器负载。

工作区已使用 Git 保存版本。后续每次功能演进都会创建提交，并为重要版本建立标签。常用回退方式：

```bash
git log --oneline
git tag
git checkout <版本标签>
```

例如回退到某个已发布版本：

```bash
git checkout v1.3.8
```

回退前建议先提交或备份当前工作区。

## 当前限制

- 响应必须是 JSON，暂不处理二进制文件和 HTML 页面数据。
- 请求体暂不支持 `multipart/form-data` 文件上传。
- 如果接口依赖 WAF、一次性签名或复杂设备指纹，直接重放请求可能失败。
- SSO 会话过期后需要重新登录目标网站，然后再次运行。
- 当前一次只运行一个抓取任务，避免对目标接口造成过高并发。
